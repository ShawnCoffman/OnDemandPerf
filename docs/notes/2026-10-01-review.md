# Review of v0.5.0 and what was done about it (2026-10-01)

Overall: well-engineered prototype (safe handles, no unsafe code, delete-on-close cleanup, fail-closed locking, candid limits).
The concerns were mostly about what the numbers mean and how they are read, not about crashes.

## Findings and status

| # | Finding | Status in 0.6.0 |
|---|---|---|
| 1 | CPU scores halved between versions, unexplained | Diagnosed from saved data, warning + opt-out added, **needs hardware confirmation** ([note](2026-10-01-cpu-score-halved.md)) |
| 2 | Random read reused the write seed, so the first 16,384 reads hit just-written blocks | Fixed: separate seed, profile `disk-qd1-v3`, regression test |
| 3 | Sequential read revisited the 1 GiB file about 15 times | Report `firstPassMBps` and `filePasses`; card shows the first pass; note added |
| 4 | RAM bandwidth was single-threaded, blind to channel count | Added multithread read/copy (`memory-v3`), up to 8 workers |
| 5 | Variation from three passes, population formula | Sample SD (n-1), median pass added; pass count still 3 |
| 6 | CPU stage throws away everything if it passes 20 s | Keeps completed stages, status `TimedOut` |
| 7 | Tray inferred stages from text prefixes and navigated JSON by string keys | `##stage` / `##report` protocol; tray deserializes `AnalysisResult`; summaries live in Core and are tested |
| 8 | Mutex of another account gave exit 2; second `/show` did nothing | Exit 3; `/show` raises the running tray's panel |
| 9 | Version hard-coded twice; hand-bumped profile strings | Version from `Directory.Build.props`; `profileHash` fingerprints parameters |
| 10 | Tray gave no signal when a hidden-panel test finished | Tray balloon with headline numbers |
| 11 | No version control; stale 1.2k-line `BuildInfo.txt`; README was a changelog; no unit tests; test output piling up | Git repo; file removed (recoverable from the baseline commit); README split into `docs/`; `tests/OnDemandPerf.Tests`; scripts clean up after themselves |
| 12 | 29 KB JSON per run, mostly static text and per-worker arrays | `/compact` single-line output added; static text not yet moved out (see open items) |
| 13 | Back-compat aliases with no consumers | Removed (schema 2.0) |
| 14 | UNC path produced a generic failure | Reported as unsupported |

## Decided not to do (yet)

- More passes with shorter duration: probably the right statistics fix, but the time budget cannot be re-validated without
  hardware, and the CPU discontinuity should be settled first.
- Hardware identity, baseline comparison, "likely causes" section, clock/thermal sampling, queue-depth-above-1 disk test,
  `/quick` profile: scoped out of this pass by choice; see [open items](open-items.md).
